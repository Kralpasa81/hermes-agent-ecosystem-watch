# 2026-07-19

## Hermes / Hermes-adjacent

- No new tagged release today; `v0.18.2` (`v2026.7.7.2`) remains latest. Three genuine changes landed on `main`:
  - **Gateway: durable delivery-obligation ledger for final responses (#67181).** Closes a long-standing gap (tracked across #58818 P1, #41696, and #63695's gateway half): a final response that was generated but not yet confirmed-delivered was the one artifact the gateway could previously lose without a trace — a crash or planned restart between finalize and platform ACK dropped it silently, and the resume path re-ran the whole turn at full cost. `gateway/delivery_ledger.py` now records every outbound final response in `state.db` before the first send attempt (`pending → attempting → delivered/failed`), with a startup sweep on dead-owner rows that redelivers or abandons them. Redelivery is explicitly labeled rather than silently retried — a recovered reply carries a visible "♻️ Recovered reply — may be a duplicate" prefix so ambiguity is never hidden. Stable dedup IDs are derived from session_key + inbound message id + content. Config: `gateway.delivery_ledger` (on by default). Validated with 30 ledger/producer tests, 352 gateway regression tests, and a cross-process E2E (record in process A, kill it mid-send, claim + redeliver in fresh process B against the same `state.db`). This is a direct reliability upgrade for anyone running Hermes gateways that can restart or crash mid-delivery.
    https://github.com/NousResearch/hermes-agent/commit/5854aad8b5
  - **Cross-agent turn-overlap tripwire fix (#64934 investigation).** The existing per-agent "one turn at a time" tripwire could never fire for a specific class of overlap: the gateway caches agents per routing key, but transcripts are owned by `session_id`, and `switch_session` (second-surface `/resume`, CLI-continuity rebinding, async-delegation pinning, topic-binding tip-walks) can map multiple routing keys onto one `session_id` without a cross-key check — so two routing keys could run concurrent turns on two different agent objects while the tripwire stayed silent. A new session_id-keyed in-flight registry (alongside the existing per-agent marker) closes that blind spot. A same-day follow-up commit exempts persist-disabled background-review forks (which share a parent's `session_id` for prompt-cache warmth but can never write to the transcript) from tripping false positives against the parent's real turn. Log-only diagnostics improvement, not a user-facing bug fix, but it directly unblocks investigation of a live routing issue.
    https://github.com/NousResearch/hermes-agent/commit/8c6627638e
  - **Desktop plugin SDK gets an i18n layer and a full developer guide.** `@hermes/plugin-sdk` now exposes `ctx.i18n` / `usePluginI18n`, letting a Desktop plugin ship its own locale bundles under its own id without touching core `en.ts` (mirrors the existing `ctx.storage` namespacing model). Paired with a new end-to-end developer guide (`developer-guide/desktop-plugin-sdk.md`) documenting the full plugin contract — contribution areas, host API, data layer, theme variables, `ctx.rest`/`ctx.socket` backend, security model — for the Desktop plugin system introduced in #60638. Relevant for anyone building or maintaining Hermes Desktop plugins/addons.
    https://github.com/NousResearch/hermes-agent/commit/360b07794b

# 2026-07-26

## Hermes / Hermes-adjacent

- **A real SQLite corruption bug in `hermes sessions optimize` was root-caused and closed.** Any raw `open()`/`close()` on a live SQLite database cancels every POSIX advisory lock the process holds on that file — including a running `VACUUM`'s exclusive lock (a documented SQLite hazard, sqlite.org/howtocorrupt.html §2.2). Hermes byte-probed live databases in hot paths (the zeroed-`state.db` detector runs on every `SessionDB` construction, which the gateway does constantly) — while `VACUUM` rewrote a file, those probes silently dropped its lock. Measured A/B on SQLite 3.50.4 with concurrent writers: raw-read path corrupted the DB in 2/2 vacuum runs with 319 vacuum errors; with the raw read removed, 0/229 vacuum errors and 0 corruption. The fix reads page metadata over the existing connection via `PRAGMA` instead of a raw byte probe, and tracks live connections so the guard is enforced rather than documented. Three follow-up review passes closed a check/use race, a read-only-connection path invisible to the guard due to URI-string path resolution, and a fail-open exception wrapper that had silently disabled the guard on error.
  https://github.com/NousResearch/hermes-agent/commit/fbd5e5772b, https://github.com/NousResearch/hermes-agent/commit/95fb477856, https://github.com/NousResearch/hermes-agent/commit/fe431651c5
- **`sessions recover --allow-partial` stopped deleting the messages it had just salvaged.** Reported in Discord: a real recovery run copied 20,817 of 20,824 message rows, then orphan cleanup deleted every one of them because the `sessions` table itself was too damaged to salvage any session row — final output was 0 sessions, 0 messages, the exact opposite of what `--allow-partial` exists to do. The fix reconstructs a minimal placeholder session row (marked `source='recovered'`, never mistakable for an original) for every orphaned `session_id` before cleanup runs, so salvaged conversation text now survives even when session metadata is unrecoverable; the outcome is still honestly reported as data loss, not a clean recovery. Three follow-up review rounds closed a related check/use race in the recovery bundle-copy path and fixed a damaged-`state_meta` case that had regressed from a loud crash into silent, unreported data loss.
  https://github.com/NousResearch/hermes-agent/commit/d2e733e636, https://github.com/NousResearch/hermes-agent/commit/c8aa0c7a34, https://github.com/NousResearch/hermes-agent/commit/9657f6e343
- **Auxiliary LLM calls (compression, title generation, vision, web search, session search, MoA) now carry the session's sticky routing key on OpenRouter and Nous Portal.** These auxiliary calls funnel through a client with no session handle, so they never sent a `session_id` routing key at all — each could land on a different provider endpoint than the conversation it served, cold-writing prompt caches that the main loop had just warmed. Fixed by resolving the key from an ambient per-conversation context variable, matching how the existing `conversation=` tag already resolves it. Fixes a community-reported issue (#70820).
  https://github.com/NousResearch/hermes-agent/commit/1c0884516c, https://github.com/NousResearch/hermes-agent/commit/f2f4df064d
- **Desktop closes two more same-shape cross-session mix-ups**, continuing yesterday's isolation fixes: a slash command run from a background tab could read the *foreground* chat's busy flag and identity, causing a brand-new idle tab to be told "session busy" (or worse, queue its command onto the visible chat's session); and terminal-started sessions were never recording their working directory at all — on one real profile this left 690 of 1,063 TUI sessions filed under "No workspace" instead of grouped by project.
  https://github.com/NousResearch/hermes-agent/commit/428c909d28, https://github.com/NousResearch/hermes-agent/commit/7ef3f1407b, https://github.com/NousResearch/hermes-agent/commit/3172b8739e
- **Windows compression-lock no longer strands every other agent on a session for a full lease window if the lock holder crashes.** The lock previously assumed any Windows holder was alive until TTL expiry; it now probes liveness with `psutil.pid_exists` (POSIX `os.kill(pid, 0)` is unsafe to reuse on Windows, where signal 0 maps to `CTRL_C_EVENT`).
  https://github.com/NousResearch/hermes-agent/commit/11c487e409

# 2026-07-21

## Hermes / Hermes-adjacent

- **Hermes Agent v0.19.0 (v2026.7.20) — "The Quicksilver Release" shipped July 20.** This is the first tagged release since v0.18.2 (Jul 8) and rolls up the whole post-v0.18.0 window (~2,245 commits, ~1,065 merged PRs, 450+ contributors). Headline changes: cold-start time-to-first-token cut **~80%** across CLI/gateway/TUI/desktop/cron (~4.3s → ~0.9s) plus reasoning-stream-by-default so you watch the model think instead of a spinner; **smart approvals** are now the default (an LLM reviewer judges flagged commands instead of prompting every time), paired with user-defined deny rules and `/deny <reason>`; new **Bitwarden and 1Password `SecretSource`** integrations so API keys no longer have to live in plaintext `.env`; **live subagent transcripts** (`tail -f` a running `delegate_task` dispatch) plus durable background-delegation delivery; the gateway's delivery-obligation ledger (tracked here Jul 19) ships as part of this release; and a `/subscription` + `/topup` flow lets you manage your Nous plan without leaving the terminal. Also: profile-based gateway message routing (one bot token, many isolated profiles), GPT-5.6/grok-4.5/kimi-k3/claude-fable-5/claude-sonnet-5 model support, and a desktop-app speed wave (14× less markdown-splitter CPU, virtualized diff review). Missed in yesterday's note because the tag landed at 18:35 UTC, after that day's check.
  https://github.com/NousResearch/hermes-agent/releases/tag/v2026.7.20

- **Fix: managed Discord agents' guild replies were being silently declined outright — now fixed.** `fix(relay): attach metadata.user_id on guild replies for egress fallback` (#68320, merged today) closes a bug where the relay adapter only attached `scope_id` (never `user_id`) on outbound guild replies, because inbound capture treated scope and author as mutually exclusive. That's fine for self-hosted setups with a static provisioned route row, but a **managed** Discord agent joins guilds dynamically at runtime and never gets one — so the connector's route lookup missed, there was no `user_id` to fall back on, and every guild reply was declined with `"discord egress declined: target not routed to an onboarded tenant"`, even though inbound messages from that same guild resolved fine. Fix captures the author's `user_id` on every inbound (DM and guild alike) so outbound replies now carry both discriminators. Direct fix for a total-loss-of-service bug on managed Discord deployments.
  https://github.com/NousResearch/hermes-agent/commit/f4df260f26c93f15694698869f3ea8e965eea301

- Desktop app gained **multi-window support** (Electron) — `⌘⇧N` / File → "New Window" now opens a full second app window (sidebar, routing, its own draft) against the same shared backend, instead of the old compact pop-out. Convenience feature, not a reliability fix.
  https://github.com/NousResearch/hermes-agent/commit/b586e4eff20de21df6a3aa1209d7d3b089df6bbc

## Broader AI agent ecosystem

- **Claude Code 2.1.216 (Jul 20)** fixes a real long-session performance bug: message-normalization cost was growing **quadratically** with turn count, causing multi-second stalls and slow resumes in long sessions. Also adds a `sandbox.filesystem.disabled` setting (skip filesystem isolation while keeping network egress control) and closes a Bash permission-check bypass for compound statements with redirects inside `&&` lists or negations, plus several worktree/session-recovery correctness fixes (worktree-isolated subagents could redirect git into the shared checkout via `git -C`/`--git-dir`/`GIT_DIR`).
  https://github.com/anthropics/claude-code/releases/tag/v2.1.216

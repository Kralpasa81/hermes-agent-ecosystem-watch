# 2026-07-15

## Hermes / Hermes-adjacent

- No new tagged Hermes Agent release today; **v0.18.2 (v2026.7.7.2)** remains latest, and curated v0.19.0 release notes covering the post-v0.18.0 window are still pending. Today's signal is entirely real correctness/reliability fixes landed on `main`:
  - **Terminal/file bounded-capture bug fix** — a prior change made the shared `execute()`/`_wait_for_process` drain (used by *every* `env.execute()` consumer, not just the terminal tool) apply a `tool_output.max_bytes` truncation limit. This silently truncated `cat` reads, paginated `read_file`, code-execution RPC reads, and log reads above 50KB — and could **corrupt read-modify-write file operations** feeding the patch engine (`read_file_raw`) for files over 50KB. Fixed by making bounded capture an explicit opt-in used only by the foreground terminal tool; the default path now preserves full-fidelity capture. New regression coverage: 200KB payloads returned intact by default, 20MB internal reads intact, byte-exact `ShellFileOperations.read_file_raw` round-trips, terminal path still correctly bounded at 50KB.
    https://github.com/NousResearch/hermes-agent/commit/cab457d722a28d60cd90d3cd6c7e5b55a12b659a
    https://github.com/NousResearch/hermes-agent/commit/0a07609173851939425f872c5f98e8000c4fe8c8
  - **Delegation fail-closed hardening** — a fresh process can no longer silently adopt a dead session's delegation results (a real correctness/security gap for CLI users); `delegate_tool`'s async dispatch now falls back to the parent agent's durable `session_id` in the CLI case instead of failing closed on an empty key.
    https://github.com/NousResearch/hermes-agent/commit/47d853fdf26415fc36de10267512dca6fd2c6f91
    https://github.com/NousResearch/hermes-agent/commit/8ff3b67e6d63d7dc7404e133292cafe59b05ceb5
  - **Streaming retry parity** — the `anthropic_messages` call path now gets the same zero-event guard and transient-retry budget the `chat_completions` path already had, and the status message for an exhausted empty-stream retry now correctly says "provider sent nothing" instead of the misleading "connection to provider failed," so users debugging a misconfigured endpoint aren't sent chasing network issues.
    https://github.com/NousResearch/hermes-agent/commit/5cbbade24c87fc9310bab43986b385a670b48113
    https://github.com/NousResearch/hermes-agent/commit/92057474f3d2dfe38c1be8900cabbae3e696cf41

## Broader AI agent ecosystem

- **Claude Code `2.1.210`** shipped security/reliability fixes on top of `2.1.208`/`2.1.209`: `isolation: 'worktree'` subagents can no longer run git-mutating commands against the main repo checkout instead of their own isolated worktree; the Agent tool is now hardened against indirect prompt injection via content a subagent read; and the `ultracode` opt-in keyword no longer fires on non-human-originated input such as webhook payloads or relayed PR comments. Also added a live elapsed-time counter for long-running tool calls and a startup warning steering users away from overly broad `Write(path)`/`NotebookEdit(path)`/`Glob(path)` permission rules.
  Source: https://raw.githubusercontent.com/anthropics/claude-code/refs/heads/main/CHANGELOG.md

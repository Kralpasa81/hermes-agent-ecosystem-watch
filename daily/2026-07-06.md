# 2026-07-06

## Hermes / Hermes-adjacent

- **Main-branch multiplex-profile routing/credential-isolation fix cluster:** Three commits landed on `main` today closing a real cross-profile leak class in multi-bot gateway deployments. `8a9bc38` fixes secondary profiles (e.g. non-default profiles running their own Telegram/Discord/etc. bot) replying through the **default profile's bot token** instead of their own across streaming, sending, media delivery, voice, typing indicators, and startup restore — the fix replaces 53 call sites that read the wrong adapter map. `ab70551` makes adapter resolution fail closed instead of silently falling back to the default profile's adapter when a secondary profile's adapter isn't registered. `0f154e7` isolates gateway config env reads per profile scope so a secondary profile no longer inherits the default profile's platform tokens or port-binding settings (fixes `#50051`). This is a meaningful reliability/security fix for anyone running Hermes with multiple bot profiles on one host. Sources: https://github.com/NousResearch/hermes-agent/commit/8a9bc38c2e72a20ed1e8b081917b6a0dd8891573, https://github.com/NousResearch/hermes-agent/commit/ab70551b3de2de49658e65476b1bdeeadc55a2f1, https://github.com/NousResearch/hermes-agent/commit/0f154e780e71c74f8a1cdccb25c97a6abd8e5a57
- **MCP parked-server wake-up fix:** `43a4256` makes `register_mcp_servers` proactively nudge cached MCP server entries whose session went stale on session startup, instead of waiting up to the parked-retry interval for the next self-probe. Improves MCP tool availability right after starting a new agent session. Source: https://github.com/NousResearch/hermes-agent/commit/43a4256320673eb1ff5a1d4389b2ac7de18d961a
- **Correction to prior tracking — issue `#33932` (OpenAI Codex `NoneType` crash) is not an open regression:** Re-checking today shows this issue is closed as a duplicate of `#33502`/`#32894`, with the durable fix already merged to `main` well before the `v0.18.0` release. Prior daily notes (July 4–5) described it as an open watch item; that framing was imprecise and is corrected here. Source: https://github.com/NousResearch/hermes-agent/issues/33932
- **Post-`v0.18.0` stale-runtime issue (`#56717`) remains open, P2:** Multiple PRs have landed to harden the stale-dashboard/profile-runtime sweep, but the issue itself is still open as of today, and a maintainer linked it to two related open bugs (`#47368` Desktop "Delete profile" silently failing, `#39136` stale `hermes dashboard --tui` processes accumulating across updates). Treat this as an ongoing multi-profile hygiene cluster rather than a single resolved bug. Source: https://github.com/NousResearch/hermes-agent/issues/56717

## Broader AI agent ecosystem

- **Claude Code `2.1.199`–`2.1.201` (July 2–3) shipped a real reliability/safety wave since the last tracked `2.1.198` baseline:** the default permission mode across CLI, VS Code, and JetBrains changed from "default" to **"Manual"**; `AskUserQuestion` dialogs no longer auto-continue by default; several background-agent daemon bugs were fixed (Linux daemon self-killing every ~50s after an unclean shutdown, stale `daemon.lock` PID reuse blocking restarts, roster corruption disabling orphan cleanup); TLS/SSL certificate errors now fail immediately with actionable guidance instead of burning retries; and subagents cut off by a rate limit now return partial work instead of silently failing. Source: https://code.claude.com/docs/en/changelog
- **GitHub Copilot GA wave (July 1–2):** Copilot CLI no longer requires a personal access token in GitHub Actions; Enterprise `managed-settings.json` reached general availability; enterprises can now default users to auto model selection; Kimi K2.7 Code and Copilot vision both reached general availability; and Copilot agent session streaming entered public preview. Source: https://github.blog/changelog/

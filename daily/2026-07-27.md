# 2026-07-27

## Hermes / Hermes-adjacent

- **Desktop ships "Artifacts": versioned cards, sandboxed live preview, right-rail viewer.** `feat(desktop): artifacts — versioned cards, sandboxed live preview, right-rail viewer` promotes substantial generated content (full HTML documents, large standalone SVGs, 48+ line / 3k+ char code fences) out of the transcript into openable, versioned artifacts instead of a wall of inline code. Detection is pure and conservative — prose, terminal output, mermaid fences, and small snippets never qualify. A per-session registry dedupes by content hash and keeps version history (same kind+title = one artifact the model iterates on, e.g. "v2 of 3 / Latest"), persisted to `localStorage` with per-session/per-artifact/byte caps. The right-rail pane adds a `PREVIEW`/`SOURCE` toggle, copy, kind-aware download, and open-in-browser for HTML — offered on click rather than auto-hijacking the transcript. A genuinely new user-facing capability, not a bug fix.
  https://github.com/NousResearch/hermes-agent/commit/236b1b56
- **A real security-relevant dependency bug closed: `hermes update` was silently downgrading already-patched environments back onto vulnerable pins.** The salvaged CVE-pin refresh in #60685 had picked pin versions that weren't actually the fixed ones — `cryptography` was pinned below the version that fixes GHSA-537c-gmf6-5ccf. Any user who had already upgraded past that pin got downgraded straight back to it on the next `hermes update`. Fixed by moving the pins to the versions that are both fixed and actually mergeable (`cryptography` 46.0.7 → 48.0.1; 49.x is blocked by `msal` and `alibabacloud-tea-openapi` caps), plus `starlette` and `python-multipart` bumps and a regenerated lockfile. The existing anti-downgrade floor guard test is kept, corrected to the right floor.
  https://github.com/NousResearch/hermes-agent/commit/623762f2
- **A gateway-hang bug class in `delegate_task` was root-caused and closed with the same fingerprint as a prior cron hang.** Delegated subagent children run through three nested daemon-thread layers; after multi-day gateway uptime the deepest layer could wedge *before the socket even opens* — zero stale-detector output, all providers affected, only a foreground restart recovered. A prior fix for a near-identical gateway-cron hang (#62151) had explicitly excluded delegation "for lack of evidence" — this is that evidence. The fix extends the existing inline-API-call gate to delegated children (detected via a delegation context marker), while leaving Codex/Anthropic/Bedrock/MoA on their established worker path; interrupts still function through the existing cross-thread abort mechanism.
  https://github.com/NousResearch/hermes-agent/commit/ece050ac (issue #60203)
- **`hermes -c` / `--resume` could resume a session from a different repo than the one you're standing in.** It resolved the *globally* most-recently-used session, then `cd`'d into that session's recorded working directory — so running `--resume` in repo A could silently land you inside repo B. It now scopes resolution to the current workspace first (the git repo root, or the CWD for non-repo directories) via the same `workspace_key` identity `hermes sessions list --workspace` already groups on, falling back to the old global-MRU behavior only when nothing matches the current workspace.
  https://github.com/NousResearch/hermes-agent/commit/28a87d63
- **A provider failover could silently double the cost of every affected turn by dropping cache breakpoints.** `apply_anthropic_cache_control` splits the system prompt into cached/volatile blocks once per call, before the retry loop; a failover firing inside that loop was overwriting the system content with a bare string to refresh the `Model:`/`Provider:` identity lines, which dropped the block structure entirely — the retried request shipped zero cache breakpoints, paid full write price for the whole system prompt, and the *next* call missed the cache too. Net effect measured directly against the real functions: a failover cost two full-price prompts instead of one write plus one read. Fixed by preserving the block structure when refreshing the identity lines.
  https://github.com/NousResearch/hermes-agent/commit/3c4220cd
- **A skill-registry integrity bug is closed: `hermes skills update` could silently hijack a skill's provenance from a different registry.** Two compounding defects: the update checker fell back to matching *any* registry with a same-named skill when the recorded source adapter didn't match, and the installer accepted a bare, registry-less identifier that could fuzzy-match a same-named skill elsewhere — together capable of deleting a user's actual skill files and rewriting the lockfile's provenance to point at the wrong source. The installer now takes an explicit source pin that aborts rather than falls back, and the update path forwards the lockfile's recorded source as that pin. Ships with regression tests reproducing the cross-registry hijack.
  https://github.com/NousResearch/hermes-agent/commit/59482ea8

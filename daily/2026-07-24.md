# 2026-07-24

## Hermes / Hermes-adjacent

- **Production cron bug fixed: direct runs left recurring jobs silently orphaned for hours.** `fix(cron): reconcile external provider after a claimed direct run` (#70479) closes a real production incident — a managed 1-minute review job stalled for **20 hours** because a GitHub-webhook direct run claimed a job's `fire_claim` about 2 seconds before the built-in scheduler's fire arrived. The direct-run winner advanced `next_run_at` but never notified the external provider, so its one-shot for that occurrence stayed stale forever and every later occurrence was orphaned — while `/api/status` kept reporting green the whole time. Fix: a claimed direct execution now calls `_notify_provider_jobs_changed_safe()` after completing so the active provider re-arms correctly. Direct reliability fix for anyone running Hermes cron jobs behind an external scheduler/provider.
  https://github.com/NousResearch/hermes-agent/commit/ef6ce56cad
- **Skills system restructured: the core `hermes-agent` skill shrank from a 51KB monolith to a ~12KB hub.** `refactor(skills): restructure hermes-agent into a hub + absorb themes, desktop-plugins, tui-widgets, petdex` (#70452) moves identity, quick start, and hard invariants into a lightweight hub with a routing table into 18 reference files carrying the depth (CLI reference, slash commands, providers/models, configuration, security/privacy, background systems, Windows quirks, troubleshooting, contributor guide, and more). Four previously separate Hermes-specific skills (themes, desktop-plugins, tui-widgets, petdex) were absorbed as references instead of standalone skills. Net effect: less context loaded per trigger, better discoverability, room to grow without re-bloating the primary body. Paired with a wider same-day sweep: 69 skill descriptions trimmed under a 60-char routing budget, several skills reclassified into more accurate categories (computer-use → autonomous-ai-agents, dogfood → software-development), and several moved to `optional-skills` (yuanbao, segment-anything, heartmula/audiocraft, jupyter-live-kernel).
  https://github.com/NousResearch/hermes-agent/commit/e3d524b482
- **Org-skill namespace lands (M2): token-gated discovery, fail-loud collisions, provenance.** `feat(skills): org-skill namespace` (#70459, paired with the sync-side client #70024) makes org-distributed skills first-class bare names instead of forcing an `org:`-prefixed naming tax. Resolution of the `_org/<org_id>/` mirror is token-gated — the activation marker is written only after the token's `org_id`/`org_role` is verified, and discovery prunes every other mirror, so a personal token that has left an org can't silently keep resolving that org's skills. Direct relevance for teams distributing shared skills across a Hermes org deployment.
  https://github.com/NousResearch/hermes-agent/pull/70459
- **Context-engine plugin ABC gains two new optional, fail-open hooks.** `feat(context-engine): select_context() + on_turn_complete() ABC verbs` (#70458, salvage of a community RFC) adds `select_context()` — the first surface verb that can *replace* which messages enter a provider request (retrieval, topic routing, role/branch switching), request-only and never mutating persisted history — and `on_turn_complete()`, a post-turn observation hook mirroring `MemoryProvider.sync_turn()` with the turn's canonical usage buckets. Both are additive, no-op by default, and fail open. Relevant for anyone building custom context-engine plugins.
  https://github.com/NousResearch/hermes-agent/pull/70458
- **MoA advisor fan-out made fault-tolerant end to end.** `fix(moa): advisor fan-out fault tolerance` (#70281) consolidates a six-PR cluster: failed advisor outputs are now contained instead of leaking raw exceptions into the acting model's input, an all-failed fan-out short-circuits instead of hanging, a user interrupt aborts the fan-out wait, advisory context is trimmed safely to each advisor's context window, quiet-CLI mode stays machine-readable, and the advisor system prompt now explicitly forbids fabricated execution claims (closing a real issue where advisors claimed to have run commands they hadn't). Also shipped same-day: `feat(moa): default advisor fanout to user_turn` (#70507), lowering the default fan-out cadence to the cheapest option pending benchmarking, and a `feat(gateway): opt-in compression progress notices` (#70457) config gate (`compression.progress_notices`, default off, byte-identical when disabled) for surfacing routine compression status to chat platforms only when explicitly enabled.
  https://github.com/NousResearch/hermes-agent/pull/70281

## Broader AI agent ecosystem

- **GitHub MCP Server ships support for the next MCP spec ahead of its official July 28 release.** GitHub's own changelog confirms the MCP protocol "is going stateless on 28th July 2026" and that the GitHub MCP Server already supports the latest spec ahead of that date. Three concrete changes: Redis-backed sessions removed entirely (no more DB writes on `initialize`, no DB reads on every call); the server no longer needs deep packet inspection of every request body for logging/secret-scanning because required values are now guaranteed present in HTTP headers; and the stdio server's URL-based elicitation was upgraded to the new multi-round-trip HTTP elicitation flow with a Go SDK compatibility wrapper for old and new clients. Also notable: MCP added official conformance tests, and tier-1 SDKs have all already shipped backward-compatible beta support. This is the strongest concrete, dated confirmation yet that the July 28 stateless-MCP cutover is real and shipping on schedule.
  https://github.blog/changelog/2026-07-23-github-mcp-server-supports-the-next-mcp-specification/
- **GitHub Issues gets agent automation controls (public preview): approvals, confidence tiers, and rationale.** As agent automations increasingly label, type, assign, and close issues, GitHub Issues now shows *why* each change happened and lets teams review before it applies. Three capabilities: suggestion-only "Approvals" that hold changes in a panel until accepted/declined; "Confidence" tiers (high auto-applies, medium/low wait for human review); and "Rationale" — an audit trail recording why each action fired, searchable via `has:suggestions`. A concrete governance pattern for anyone letting agents touch issue triage at scale.
  https://github.blog/changelog/2026-07-23-agent-automation-controls-in-github-issues-in-public-preview/
- **Copilot cloud agent for Linear reached general availability.** Linear issues can now be assigned directly to GitHub's asynchronous background coding agent, which opens a draft PR, works in its own ephemeral GitHub Actions environment, streams progress into the Linear activity timeline, and requests review on completion. GA adds per-issue/workspace model choice, custom-agent selection, base/working-branch control, and mid-session steering via comment mentions.
  https://github.blog/changelog/2026-07-23-copilot-cloud-agent-for-linear-is-now-generally-available/

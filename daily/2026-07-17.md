# 2026-07-17

## Hermes / Hermes-adjacent

- No new tagged release today; `v0.18.2` (`v2026.7.7.2`) remains latest, with curated `v0.19.0` release notes for the post-v0.18.0 window still pending. `main`-branch activity today is reliability hardening, not user-facing features:
  - **Session auto-title race conditions closed** — a cluster of fixes landed together: `set_auto_title_if_empty` adds a collision-dedup retry (so two sessions auto-titled at the same time no longer clobber each other, e.g. producing `"Weekly Report #2"` instead of silently overwriting), auto-title writes are now atomic, and generation no longer overwrites a title the user set manually while generation was in flight (predicate failure returns `None`, nothing written). Cron-triggered title generation (`#50535`–`#50537`) is covered by the same hardening, and legacy stores without the atomic method keep the old path for compatibility.
    https://github.com/NousResearch/hermes-agent/commit/7facf63ae71b846d6079a69483fc95ce9aa8db75
  - **TUI mouse-tracking deadlock fix** (#66080) — when a terminal's own "disable mouse reporting" toggle (or tmux, or another app) clears the DEC mouse modes, mouse-only users were stuck: every existing recovery path (resize, stdin-gap+keypress, raw-mode bounce) needed stdin, and losing mouse reporting is exactly why no stdin arrives. A new watchdog DECRQM-probes mode 1000 every 2s while tracking is expected on and re-arms it automatically if the terminal reports RESET, with zero added query traffic during normal use and auto-disable on terminals that don't answer DECRQM. Previously required a window resize to recover.
    https://github.com/NousResearch/hermes-agent/commit/46d16f4c2822722370168bd06a251ad5c193bebc
  - Also landed: Honcho integration follow-ups (timeout-staleness check memoized against `config.yaml` mtime instead of a full YAML reload per call, host-aware status cadence display) — internal correctness/perf polish, not user-facing.
    https://github.com/NousResearch/hermes-agent/commit/04d84df63cb66603afafef50fb13615b3855a4e0

## Broader AI agent ecosystem

- **Claude Code `2.1.212`** (Jul 17) — adds a session-wide WebSearch call cap (default 200, `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`) and a per-session subagent-spawn cap (default 200, `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`) to stop runaway search/delegation loops; MCP tool calls running over 2 minutes now auto-background so the session stays usable; `/fork` now copies a conversation into a real background session instead of an in-session subagent (that role moves to the new `/subtask`); added `claude auto-mode reset`. Also fixes plan mode silently auto-running file-modifying Bash commands without a permission prompt, and a `continue:false` hook halt being dropped when a tool fails mid-stream.
  Source: https://raw.githubusercontent.com/anthropics/claude-code/refs/heads/main/CHANGELOG.md
- **OpenAI Codex/ChatGPT unified desktop app — widespread freeze reports after the July 17 update** — multiple independent threads (OpenAI community forum, Reddit r/codex) report the new unified ChatGPT/Codex desktop app on Windows going fully unresponsive ("blue loading cursor", "Not Responding") on every click after receiving today's update; separate reports describe banked Codex usage resets disappearing from the UI in the same build. This compounds the capacity/reliability strain already flagged this week following the GPT-5.6 usage surge (Jul 14–16).
  Sources: https://www.reddit.com/r/codex/comments/1uyqbzl/probleme_lag_last_update/, https://community.openai.com/c/chatgpt/bugs/23

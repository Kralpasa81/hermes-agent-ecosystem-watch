# 2026-07-22

## Hermes / Hermes-adjacent

- **Gateway fix generalizes the "stranded platform" recovery to every adapter, not just Discord/Telegram.** `fix(gateway): make adapter fatal-error handoff cancellation-proof; exit if a platform is stranded` (#69112, merged today) closes #68693, plus related reports on qqbot (#25505/#29005) and photon (#68693). Root cause: the fatal-error notification ran on the failing adapter's own polling task, and `adapter.disconnect()` inside the handler could cancel that same task via a guard miss — the `CancelledError` killed the handler between the fatal log and the reconnect queue, leaving a platform permanently dead inside an otherwise-live gateway process, invisible to `launchd`/`systemd` `KeepAlive`. The fix runs the real handler in a detached task shielded from cancellation, and if a retryable platform still ends up neither reconnected nor queued, the gateway now hard-exits so the process manager restarts it. #68447 fixed this for Telegram specifically on July 21 (tracked in yesterday's note); this hardens the *shared* gateway dispatch path so it protects every platform.
  https://github.com/NousResearch/hermes-agent/commit/2ab153218ba401525ec02380305f8c3c4c8b1dc0

- **`hermes update` fleet restarts no longer abort mid-way on one slow gateway unit.** `fix(update): isolate systemctl timeouts so fleet gateway restarts continue` (#69117, closes #68523) fixes a bug where a single `TimeoutExpired` from one `hermes-gateway*.service` used to abort the *entire* per-scope restart loop, silently leaving later profile gateways running stale pre-update in-memory code after `hermes update`. Timeouts are now caught per-unit, the fleet restart continues, a warning names the exact stale units, and the command exits non-zero if any remain unrestarted. Direct correctness fix for anyone running multiple Hermes gateway profiles on one host.
  https://github.com/NousResearch/hermes-agent/commit/e99882c2d91bd323a55529e49ac29a3cb9d77fb8

- **Cold-resume session duplication bug fixed.** `fix(cli): pass conversation_history on /new /resume /branch flush` (closes #68454) fixes a bug where transcript rows restored from a cold resume lacked the internal "already persisted" marker until a normal turn flush stamped it — so an immediate `/new`, `/resume`, or `/branch` right after resuming would flush with no history boundary and re-append every restored row into the old session, duplicating it. Mirrors an earlier fix (#68205) for the same root cause at three additional call sites.
  https://github.com/NousResearch/hermes-agent/commit/1c0a57832bd2c0d76e7808fefaad06e2c9fdba05

- **Context-compaction correctness pass**: three related fixes landed today — `fix(compression): prevent stale-budget retry loops` (a direct-started `--model`/`-m` process could carry a stale `context_length` override from the config-default model into a different active model, causing incorrect budget math), `fix(compression): ignore assistant handoff summaries in tail anchor` (compaction summaries were being mistaken for the last visible assistant reply once head protection decayed, pulling the tail boundary back to the summary itself and leaving zero new turns to summarize), and `fix(compression): harden startup route scoping`. Incremental reliability work on the compaction pipeline, not user-facing features.
  https://github.com/NousResearch/hermes-agent/commit/377244f7c825a2c6c8e29ac485eb01d038f4432b

- **Telegram group-chat authorization fix.** `fix(telegram): group authz fallback + command sender identity` (PR #69154, salvage of #67816) separates `group_allow_from` (groups) from `allow_from` (DMs), adds a `config.extra` fallback for group authorization when observe-unmentioned mode strips `user_id` from the env-var check, and preserves sender identity on command messages so admin-only slash commands actually work inside groups. Practical fix for anyone running Hermes as a Telegram bot in group chats.
  https://github.com/NousResearch/hermes-agent/commit/45fce38b9edd426616a08ffcbadf866fa7070934

- Smaller feature work merged today, none release-critical: a cross-surface **theme SDK** (one skin drives CLI, TUI, and desktop live), a TUI **widget-app SDK** (apps as state+reducer+render, three reference apps), and a **billing UX bundle** (desktop Billing page revamp with in-app plan browsing, native chargeless-preview downgrade flow, and CLI `/subscription` plan catalog on Free). No tagged release yet since v0.19.0 "Quicksilver" (Jul 20) — today's commits are accumulating toward the next one.

## Broader AI agent ecosystem

- **Claude Code 2.1.217 (Jul 21)** adds real guardrails against runaway subagent fan-out: a default cap of 20 concurrently-running subagents (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`), subagents no longer spawning nested subagents by default, and a fix so `--max-budget-usd` actually stops background subagents once the cap is hit (previously it didn't). Also fixes a memory leak where truncated MCP tool outputs kept the full untruncated result in memory for the rest of the session, and Windows auto-update failures that could leave `claude.exe` missing entirely. Direct cost-control and reliability signal for anyone running Claude Code with subagents at scale.
  https://github.com/anthropics/claude-code/releases/tag/v2.1.217

- **OpenAI Codex CLI `0.145.0` shipped stable (Jul 21)** after two weeks of alpha churn since `0.144.6`. Headline features: experimental paginated thread history with resume/search/persisted names/memories; `/import` expanded to migrate settings, MCP servers, plugins, sessions, commands, and project memories from **Cursor and Claude Code**; experimental Amazon Bedrock login with GPT-5.6 Sol as the default Bedrock model; audio inputs/outputs and streaming realtime v3; and the opt-in multi-agent v2 experience stabilized. Alpha churn resumed immediately after (`0.146.0-alpha.1/2`, Jul 22) with no further stable tag yet.
  https://github.com/openai/codex/releases/tag/rust-v0.145.0

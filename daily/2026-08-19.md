# 2026-08-19

## Hermes / Hermes-adjacent
- **Hermes Agent `v0.20.6`** (Aug 18) now current — this is a maintenance release that fixes a regression in prompting that caused delayed responses in some complex skills when decoding nested objects and that specifically broke the `parse_xml` tool's error handling; it also adjusts web-extracted JSON parsing for malformed vendor responses ([`#78257`](https://github.com/NousResearch/hermes-agent/pull/78257), [`#78299`](https://github.com/NousResearch/hermes-agent/pull/78299), [`#78301`](https://github.com/NousResearch/hermes-agent/pull/78301))
- **`hermes skill ban`** (Aug 18) gains a `-w`/`--wait` flag (default 30s background timeout) — if Hermes is a gateway, this lets workflows orchestrate ban propagation more reliably by waiting for known backends to fully ban and cache ([`#77290`](https://github.com/NousResearch/hermes-agent/pull/77290))
- MCP policy now recognizes `preference.mcp.read_permission.*` statements ([`#78237`](https://github.com/NousResearch/hermes-agent/pull/78237)) and file_upload/download permission ([`#78238`](https://github.com/NousResearch/hermes-agent/pull/78238)) from next-generation servers sending standardized permissions schemas over MCP.
- Approval policy now shows a consistently formatted reason line for tool_call rejections regardless of whether there were nested calls that also required approval ([`#78001`](https://github.com/NousResearch/hermes-agent/pull/78001))
- Tool_call error cache keys now include the full tool `arguments` dictionary — cached errors no longer persist if a new call changes any argument values ([`#77442`](https://github.com/NousResearch/hermes-agent/pull/77442))

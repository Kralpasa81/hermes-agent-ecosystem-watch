# 2026-08-02

## Hermes / Hermes-adjacent

- **A high-severity data-loss bug in `hermes skills install` is closed.** Installing a skill by name with `hermes skills install <url> --name <name>` was doing an unconditional, unconfirmed `rmtree` on `<skills_dir>/<name>` before installing — even when that path was a *category bucket* holding many unrelated skills, and even with `--yes` skipping the normal confirmation prompt. The bug report that triggered the fix cites 16 unrelated skills destroyed in one incident. Fixed by sharing category detection and guarding the install path against wiping category directories or colliding with hybrid nested skill dirs.
  https://github.com/NousResearch/hermes-agent/issues/75983
- **A Node 26 runtime requirement (`feat(runtime)!:`) triggered several hours of install breakage across installers, then got fully stabilized same-window.** The bump (`engines.node >=20` → `>=26`, all installers/Docker/nix/CI moved to Node 26) landed just after midnight UTC and immediately hit toolchains that couldn't meet the new floor — npm engine failures, a stale lockfile-engines mirror still gating desktop on the old floor, `hermes_constants` caches surviving from before the update, and Desktop E2E going red on every PR. Nous shipped a rapid string of fixes through the morning (npm 12 provisioned into the vendored Node tree on both Windows and Linux, engine range relaxed for Node 22/npm 11, lockfile mirrors resynced, managed-Node/uv resolution hardened) and the CI lane was stabilized by ~04:30 UTC. Net: a real breaking change that briefly blocked fresh installs/updates for some users, resolved within the same day.
  https://github.com/NousResearch/hermes-agent/commit/713a983e
- **A secret-scope migration wave closes the last cross-profile credential leaks under gateway multiplexing.** A consolidated salvage of five contributor fixes routes `/compress`, Matrix recovery-key reads, Discord/HASS/Camofox model-tool credential reads, cold-profile BWS/1Password hydration, and WhatsApp env reads through the per-profile secret scope instead of falling back to `os.environ` or throwing `UnscopedSecretError`. Each fix was re-verified against the profile-boundary rule (isolation between sibling profiles; a profile's own subagents/cron/review-forks/bridge subprocesses still inherit its secrets).
  https://github.com/NousResearch/hermes-agent/pull/76573
- Also today: CAPTCHA-aware, actionable guidance on Nous device-auth timeouts, now applied at the source so both the CLI login and the dashboard's poller surface the same helpful message instead of a bare timeout string.
  https://github.com/NousResearch/hermes-agent/pull/76649

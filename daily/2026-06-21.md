# 2026-06-21

## Hermes / Hermes-adjacent

- **Hermes Agent latest tagged release remains `v0.17.0` / `v2026.6.19` (“The Reach Release”).** No newer tagged Hermes release was found today, so the release remains the primary baseline for the repo. Source: https://github.com/NousResearch/hermes-agent/releases/tag/v2026.6.19
- **Hermes main added important cron reliability follow-up work after the release.** The in-process cron ticker now survives `BaseException`, writes a heartbeat, and lets `hermes cron status` report a stalled ticker instead of falsely saying jobs will fire while the gateway process is still alive. Source: https://github.com/NousResearch/hermes-agent/commit/07424da76f60ce1efee5239e9d324a3069873494
- **Cron delivery confirmation was hardened to avoid duplicate sends and silent drops.** Hermes now treats live-adapter confirmation timeouts as already dispatched instead of replaying the same message through fallback delivery, requires explicit success from adapter result objects, and handles unresolvable CLI-origin delivery more safely. Source: https://github.com/NousResearch/hermes-agent/commit/d54890870ffd50a596b1ba0272bc05889e3e35c7
- **Cron model resolution now fails early with an actionable error instead of sending an empty model to providers.** This matters for unattended jobs created without an explicit model because `model.default`, `model.model`, environment fallback, and managed-scope overlays are now handled more consistently. Source: https://github.com/NousResearch/hermes-agent/commit/73b92264ee08cc25dfee3b8854ce0c94f6534a5b
- **Long-session and memory-tool reliability also improved on main.** Context compression now lets the early-turn protection decay after the first compaction so old turns do not become permanently fossilized, and single-op memory replace/remove can recover when `old_text` is missing by returning inventory plus retry guidance. Sources: https://github.com/NousResearch/hermes-agent/commit/14ef6312b5ccab71799620ef76ac0d4335b535ae, https://github.com/NousResearch/hermes-agent/commit/c6bf6bda90a2bba718f94dc8fc69dcaf7828819e

## Starred signals today

- ⭐ **Hermes cron ticker heartbeat + stalled-status reporting** because scheduled automations are a core Hermes workflow, and operators need to know when the gateway is alive but the cron ticker is not firing jobs.
- ⭐ **Hermes cron delivery confirmation hardening** because unattended scheduled jobs should not duplicate result messages on timeout or silently drop results when adapter success is ambiguous.
- ⭐ **Hermes cron model-resolution fail-fast behavior** because scheduled work should fail with an actionable configuration error instead of surfacing opaque provider-side empty-model errors.
- ⭐ **Hermes compression and memory recovery fixes** because long-running sessions and persistent memory updates are foundational to Hermes’ “agent that grows with you” workflow.
